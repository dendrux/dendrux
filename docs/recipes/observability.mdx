# Observability

The recorder durably writes runs, events, traces, tool invocations and LLM usage.
Notifiers deliver live callbacks; `OpenTelemetryNotifier` connects those callbacks
to the tracer provider and exporter configured by your application. Use RunStore
reads plus your own tracing and operator UI. Dendrux does not supply a historical
timeline projection or operator interface.

## Inspect a run with bounded reads

This is an internal operator script, not a browser response. Authenticate and
authorize any route built around it, including user-level ownership within a tenant.

```python
from dendrux.store import RunStore

async def inspect_run(database_url, run_id, tenant):
    async with RunStore.from_database_url(database_url) as store:
        detail = await store.get_run(run_id, tenant_id=tenant)
        if detail is None:
            return None
        pending = await store.get_pending(run_id, tenant_id=tenant)
        pauses, truncated = await store.get_pause_page(run_id, tenant_id=tenant, limit=100)
        events = await store.get_events(run_id, tenant_id=tenant, limit=100)
        safe_events = [await store.get_event_view(run_id, e, tenant_id=tenant) for e in events]
        print("status", detail.status, "cost", detail.total_cost_usd)
        print("pending", pending.kind if pending else None)
        print("pause pairs", len(pauses), "truncated", truncated)
        for event in safe_events:
            print(event.sequence_index, event.event_type, event.created_at)
        print("next event cursor", events[-1].sequence_index if events else None)
        return detail.status
```

Page events using `after_sequence_index` and an explicit row limit. Each
`get_event_view` call queries run status and may also read active-pause context;
keep inspection pages small because this adds at least one query per event. Treat a full
page as potentially incomplete; retain the cursor. `get_pause_page` returns an
explicit truncation flag. Build any historical join of events, traces, tools and
usage in your app, with row/byte/time bounds and visible truncation. A pending pause
and live event feed do not replace a normalized historical timeline. For a stuck
approval, combine pending state with pause timestamps; for costs, inspect totals
and bounded `get_llm_calls` pages. Reads may intentionally contain personal data.

For terminal inspection without a web service:

```bash
dendrux runs --tenant acme --limit 50
dendrux traces RUN_ID --limit 100
```

The traces command is a trusted local operator tool and can print raw content;
apply your normal database-access controls. It is not an end-user API.

## Connect tracing

```python
from dendrux.notifiers import CompositeNotifier, ConsoleNotifier
from dendrux.notifiers.otel import OpenTelemetryNotifier

notifier = CompositeNotifier([ConsoleNotifier(), OpenTelemetryNotifier()])
result = await agent.run("Inspect this order", tenant_id=tenant, notifier=notifier)
```

Install `dendrux[otel]` and configure your application's tracer provider and exporter.
The recorder is the durable audit source; notifier failures are fail-open and live
callbacks are not a substitute for persisted evidence. Correlate run IDs with your
request IDs, actor/approval audit records and traces. See [OpenTelemetry](/docs/recipes/opentelemetry)
and [Notifier](/docs/architecture/notifier).

For optional live inspection use [Build your own read routes](/docs/recipes/build-your-own-read-routes):
`follow` batches its reads for every watched run and bounds iteration, while your transport bounds sends and
closes every follower in `finally`. Keep raw provider payloads and PII mappings
behind operator authorization; never copy an entire RunResult into a browser DTO.

## What to alert on

Structured log lines carry a stable `code`. Group alerts by that field and correlate with `run_id`; do not parse message text or export tool payloads. The generated [Log codes](/docs/reference/log-codes) reference lists levels, fields and suggested actions.

| Code | Alert policy and action |
| --- | --- |
| `reclaim_limit` | Any occurrence: inspect repeated worker loss and the run's recovery history |
| `lease_renew_failed`, `lease_lost` | Sustained renew failures or any lost lease: inspect database latency, availability and event-loop stalls |
| `run_fenced` | A small burst after reclaim is expected; a sustained rate calls for checking worker turnover and lease sizing |
| `live_updates_degraded` | Lasting over one minute: inspect the listener's connection to the bus (for Postgres, the primary through a direct or session-pool endpoint). Readers poll meanwhile |
| `live_updates_unavailable` | The listener cannot become ready: check reachability and the channel; reads use polling and retry after 30 seconds |
| `live_updates_missed_hint` | A healthy safety poll found new events that no hint announced, once per watched run: verify that every writer's store has live updates on the same bus and channel as the readers |
| `live_updates_send_failed` | A writer's announcement failed and sending is backing off. The database commit is unaffected; check the bus. Sustained, the writer's readers fall back to the safety poll |
| `live_updates_overflow`, `live_updates_many_stores` | Pending announcements overflowed, or a process holds many open stores for one database: share one store per database and close the rest |
| `follow_read_failed`, `follow_coordinator_restart` | A reader's batched read failed, or its coordinator restarted: check store connectivity. Other chunks and the followers continue |
| `write_conflict` | Any occurrence: inspect conflicting writer identities or content before retrying |
| `activation_conflict` | Activation found conflicting duplicates: resolve the reported table/index conflict before retrying |
| `checkpoint_too_large`, `history_too_large`, `pending_limit` | Inspect the run's configured bounds and reduce state or fanout; do not continue with truncated history |
| `recovery_call_missing`, `recovery_state_missing`, `recovery_state_invalid`, `loop_unknown` | Inspect stored recovery state and the deployed Agent/store versions |
| `cascade_truncated` | Inspect the remaining subtree and cancel branches explicitly, or raise `Budget.max_subtree_nodes` |
| `sweep_cap_reached`, `tool_pool_saturated` | Sustained rate: inspect backlog and worker capacity; keep dispatch bounded |
| `provider_unknown` | Inspect the safe provider category and HTTP status; unknown vendor codes have no public mapping |
| `database_url_env_ignored` | The Agent ignored an environment database URL and has no persistence: pass `state_store=` or `database_url=`; this warning is logged once per process |

On Postgres, also alert on sustained growth in `pg_notification_queue_usage()` when live updates are enabled. A stuck listener can fill the queue; announcements then fail and back off, and the saves themselves are unaffected. A `live_updates_recovered` log signals reconnection and `live_updates_send_recovered` that sending works again; confirm reader latency recovers too. `store.live_updates.stats()` shows pending and dropped counts and the age of the oldest stranded hint. The other live-update codes are in [Log codes](/docs/reference/log-codes).

Strict log-field validation is enabled only with `DENDRUX_STRICT_LOG_FIELDS=1`. In normal operation invalid fields are dropped and reported by `log_field_dropped`. Keep production diagnostics to codes, ids, counts and kinds.

For recovered runs, inspect `RunResult.recovery` or the `recovery` envelope field from `agent.get_result`, plus the `run.lease_expired`, `run.reclaimed` and `tool.replayed` events. The replayed-call list is bounded; check `replayed_truncated`. With `OpenTelemetryNotifier`, persisted trace links keep resume and reclaim in the original trace across processes. See [Recovery](/docs/guides/recovery) and [OpenTelemetry](/docs/recipes/opentelemetry#one-trace-per-run).
