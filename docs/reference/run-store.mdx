# RunStore

`RunStore` is the public, read-only way to query everything Dendrux persisted about a run. It is a plain Python object you can call from any code (routes, admin scripts, background jobs) it supports routes and inspection tools owned by your app.

```python
from dendrux.store import RunStore

store = RunStore.from_database_url("sqlite+aiosqlite:///app.db")
async with store:
    run = await store.get_run(run_id)
    events = await store.get_events(run_id)
```

## Constructors and lifecycle

```python
@classmethod
def from_database_url(database_url: str) -> RunStore     # store owns the engine
@classmethod
def from_engine(engine: AsyncEngine) -> RunStore         # caller owns the engine
async def close() -> None
```

Both constructors also take `blob_store=` (a `BlobStore`) when the deployment keeps image bytes outside the database; use the same store as the `Agent`. Two members relate to images:

```python
store.blobs                                                       # BlobAccessor: read, info, references, purge, collect_garbage
async def read_image(run_id: str, sha256: str, *, tenant_id=...) -> bytes
```

`read_image` returns verified image bytes only if the run exists (and matches `tenant_id` when given) and references that blob; otherwise `BlobNotFoundError`, the same error for a missing blob, another tenant's blob and an unreferenced one. It is the call to put behind your own authorization when you serve images from a route. `store.blobs.purge(...)` and `store.blobs.collect_garbage(...)` are the only writes `RunStore` has. See [Images](/docs/recipes/images#storage).

`from_database_url` creates and owns an engine; `close()` (or exiting the `async with`) disposes it. `from_engine` reuses an engine you already have; `close()` is then a no-op and you dispose the engine yourself. `RunStore` is an async context manager.

## Tenant scope

Every read takes a keyword-only `tenant_id: TenantScope = UNSCOPED`, where `TenantScope` is `str | None | UNSCOPED`:

| Value | Reads |
| --- | --- |
| `"acme"` | that tenant's runs only |
| `None` | untenanted runs only (changed in 0.5.0: `None` used to mean "all" on `list_runs` and `count_runs`) |
| `UNSCOPED` (the default) | every tenant |

A run outside the scope behaves exactly like a missing one: `get_run` returns `None`, and the other per-run reads raise `RunNotFoundError`. The scope is part of the same query as the read. `get_subtree`, `get_notes` and `read_image` already took a tenant and work the same way. Pass the authenticated caller's tenant from every route of your own; see [Multi-tenancy](/docs/architecture/multi-tenancy).

```python
from dendrux import UNSCOPED
```

## Read methods

```python
async def list_runs(
    *,
    status: str | list[str] | None = None,
    agent_name: str | None = None,
    parent_run_id: str | None = None,
    tenant_id: TenantScope = UNSCOPED,
    started_after: datetime | None = None,
    started_before: datetime | None = None,
    metadata_filter: dict[str, Any] | None = None,
    limit: int = 50,
    offset: int = 0,
) -> list[RunSummary]

async def count_runs(*, status=..., agent_name=..., parent_run_id=...,
                     tenant_id: TenantScope = UNSCOPED, started_after=..., started_before=...,
                     metadata_filter=...) -> int

# every method below also takes tenant_id: TenantScope = UNSCOPED
async def get_run(run_id: str) -> RunDetail | None
async def get_events(run_id: str, *, after_sequence_index: int | None = None,
                     limit: int | None = None, event_types: list[str] | None = None,
                     before: datetime | None = None) -> list[StoredEvent]
async def stream_events(run_id: str, *, after_sequence_index: int | None = None,
                        poll_interval_s: float = 0.5) -> AsyncIterator[StoredEvent]
async def get_llm_calls(run_id: str, *, iteration=None, limit=None, offset=0,
                        before: datetime | None = None) -> list[LLMCall]
async def get_tool_invocations(run_id: str, *, iteration=None, limit=None, offset=0,
                               before: datetime | None = None) -> list[ToolInvocation]
async def get_traces(run_id: str, *, limit=None, offset=0) -> list[TraceEntry]
async def get_pauses(run_id: str) -> list[PausePair]
async def get_pii_mapping(run_id: str) -> dict[str, str]
async def get_subtree(run_id: str, *, tenant_id: str | None = ...) -> RunSubtree
async def get_notes(run_id: str, *, undelivered_only: bool = False,
                    tenant_id: str | None = ...) -> list[RunNote]
```

| Method | Returns | Notes |
| --- | --- | --- |
| `list_runs` | `RunSummary` page | Filters AND together. `metadata_filter` is exact-match across `meta` keys. |
| `count_runs` | `int` | Same filters as `list_runs`, for pagination totals. |
| `get_run` | `RunDetail` or `None` | One run's full anchor row. |
| `get_events` | `StoredEvent` list | `after_sequence_index` is a strict `>` cursor (reconnect-safe). See [Event ordering](/docs/architecture/event-ordering). |
| `stream_events` | async iterator | Raw events, never ends on its own. Without `tenant_id` it reads any tenant's run and prints a `DeprecationWarning`; prefer `follow`. |
| `get_pending` | `PendingPause` or `None` | What a paused run is waiting on. See [Pending and live reads](#pending-and-live-reads). |
| `follow` | `Follow` (async iterator) | A hardened live feed. See [Pending and live reads](#pending-and-live-reads). |
| `get_llm_calls` | `LLMCall` list | Per-LLM-call usage, cache, raw payloads. |
| `get_tool_invocations` | `ToolInvocation` list | Per tool execution: params, result, success. |
| `get_traces` | `TraceEntry` list | Conversation messages in order. |
| `get_pauses` | `PausePair` list | HITL pause/resume cycles. |
| `get_pii_mapping` | `dict[str, str]` | Placeholder to real value. See [PII redaction](/docs/architecture/pii-redaction). |
| `get_subtree` | `RunSubtree` | A run, its delegated descendants and live rolled-up usage. |
| `get_notes` | `RunNote` list | Inbox notes submitted with `submit_note`, delivered or not. |

### Pending and live reads

Two calls exist to serve a frontend from your own routes. Both require an explicit `tenant_id` (a string, `None`, or `UNSCOPED`; leaving it out is a `TypeError`) and never fail open. The recipe is [Build your own read routes](/docs/recipes/build-your-own-read-routes).

```python
async def get_pending(run_id: str, *, tenant_id: TenantScope) -> PendingPause | None

def follow(run_id: str, *, tenant_id: TenantScope, after_sequence_index: int | None = None,
           include_payloads: bool = False, until_terminal: bool = True,
           max_duration_s: float | None = 900.0) -> Follow
```

**`get_pending`** returns `None` when the run is not paused and raises `RunNotFoundError` for a missing or foreign run. A `PendingPause` has `run_id`, `status`, `kind` (`client_tool`, `approval`, `input` or `paused`), `pause_id`, `tool_calls` (a list of `PendingToolCall` with `id`, `name`, `target`, `params` and `approval`), `question`, `options`, `reason`, `message` and `budget_exceeded`; `to_dict()` gives the `run.paused` event shape plus those fields. It is one bounded read; the run's history is never loaded. `params` are the active pause's arguments, visible by default (the instruction to the client). It reports the run you ask about: for a run that delegated, list the tree with `get_subtree` and call `get_pending` for each waiting node.

**`follow`** yields `StoredEvent` items, `FollowHeartbeat` when quiet, and a final `FollowEnd(reason, cursor)` where `reason` is `terminal`, `max_duration`, `lagging` or `error`. Use `async for` (after `await follow.start()` if you want to check the scope and capacity before sending response headers) and `await follow.aclose()` when done. A shared poller serves every follower of a run in your process, at most 500 followers per store (`FollowCapacityError`, answer 503), 900 s per follow by default. Events pass through `redact_event`: with `include_payloads=False` the system prompt, provider bodies, the PII mapping and past pauses' arguments are removed, and the active pause's arguments stay.

**`get_event_view(run_id, event, *, tenant_id, include_payloads=False)`** verifies the
scoped run and event association, resolves the active pause, and uses recorded
model-sent approval arguments. Prefer it when paging raw `get_events` rows for a UI.
`follow` applies this contextual projection automatically. Neither makes raw traces,
run details or provider records suitable for a browser without your field allowlist.

**`redact_event(event, *, include_payloads=False, active_pause=False)`** is a conservative
standalone filter with no database context. Unverified active approval/input params
are hidden (`params=None`, `args_hidden=True`); never replace them with empty args.
Use `get_event_view` for the verified model-sent values. All feed and pending types,
`EventFeed`, `redact_event` and `RunStore` are importable from `dendrux.store`.

Client-tool params may contain real personal data under the default PII restore
policy. Authenticate and authorize user-level run ownership before exposing them.
The feed bounds iteration; your HTTP transport must bound blocked sends and call
`aclose()` in `finally`, including if no generator iteration begins.

Integration note: `pause_id` remains None until the run-integrity track lands.

### `get_subtree`

A delegated run has child runs, which may have children of their own. `get_subtree` returns the whole tree under a run, with usage rolled up:

```python
tree = await store.get_subtree(run_id)
for node in tree.nodes:                       # breadth-first, root first
    print("  " * node.depth, node.run.run_id, node.run.status, node.usage.known_cost_usd)
print(tree.usage.input_tokens, tree.usage.output_tokens, tree.usage.cost_usd)
```

- `RunSubtree` has `root_run_id`, `nodes` (a `SubtreeNode` each: `run` as a `RunSummary`, `depth` below the root, and that run's own `usage`), `usage` (the sum over every node) and a `root` property.
- `RunUsage` has `input_tokens`, `output_tokens`, `cache_read_tokens`, `cache_write_tokens`, `reasoning_tokens`, `cost_usd`, `known_cost_usd`, `unpriced_calls` and `llm_calls`. `known_cost_usd` is the sum over the priced calls; `cost_usd` equals it only when every call was priced and is `None` when any was not (an unknown cost is never counted as zero).
- **`RunSubtree.usage` is the live rollup of successfully recorded `llm_interactions`.** It includes unfinished runs, but interaction writes are best-effort, so it is not a billing guarantee. The `total_*` fields on each node's `RunSummary` are the snapshots persisted on `agent_runs` and may lag, or read 0 for a run still in progress. Use `usage` for live spend; this is also the figure [budgets](/docs/architecture/budget) enforce.
- The reads are best-effort, not one snapshot transaction. A run that is still writing can make the node list and the usage differ by a call or a child.
- **Tenancy.** Omit `tenant_id` (or pass `UNSCOPED`) for a trusted, unscoped read of all descendants. Pass a string to scope to that tenant, or an explicit `None` to scope to untenanted runs. The root must be in scope (otherwise it reads as missing) and so must every descendant; a run outside the scope is excluded together with everything below it.
- Raises `RunNotFoundError` if the root does not exist or is out of scope.

### `get_notes`

```python
notes = await store.get_notes(run_id, undelivered_only=True)
```

The run's [inbox](/docs/architecture/inbox) notes as `RunNote` records (`note_id`, `run_id`, `text`, `metadata`, `created_at`, `delivered_at`, `delivered_iteration`) in delivery order. `delivered_at` is `None` for a note the model has not seen. With `tenant_id=` the run must belong to exactly that tenant or `RunNotFoundError` is raised; without it, a missing run gives an empty list.

> Since 0.5.0 `dendrux.store.RunNotFoundError` and `dendrux.errors.RunNotFoundError` are the same class, constructed from a run id (`RunNotFoundError("01J...")`). One `except` clause covers `Agent` methods and `RunStore` reads. Code that raised it with a message must pass the run id instead.

### Time and type filters

`get_events`, `get_llm_calls` and `get_tool_invocations` accept `before=`, an exclusive upper bound on `created_at`. It must be timezone-aware; a naive datetime raises `ValueError`. `get_events` also accepts `event_types=`, a list of event type strings to keep (an empty list matches nothing):

```python
from datetime import UTC, datetime

governance = await store.get_events(run_id, event_types=["policy.denied", "approval.requested"])
old = await store.get_llm_calls(run_id, before=datetime(2026, 10, 1, tzinfo=UTC))
```

### `metadata_filter`

`list_runs` and `count_runs` accept `metadata_filter: dict[str, Any]` (the HTTP router does not expose this). It does exact-match equality across every key in the run's `meta` JSON, AND across keys (`jsonb @>` on Postgres, repeated `json_extract` on SQLite). Keys are restricted to `^[A-Za-z0-9_-]+$`; nested paths are out of scope. The canonical use is per-conversation observability:

```python
runs = await store.list_runs(metadata_filter={"thread_id": "thread_abc"})
total = await store.count_runs(metadata_filter={"user_id": "u_123"}, status="error")
```

See [Chatbot threads](/docs/recipes/chatbot-threads) for the full pattern.

## Record types

All returned from `dendrux.store`. Fields, exact as persisted:

**`RunSummary`** (from `list_runs`): `run_id`, `agent_name`, `status`, `created_at`, `updated_at`, `iteration_count`, `total_input_tokens`, `total_output_tokens`, `total_cache_read_tokens`, `total_cache_creation_tokens`, `total_cost_usd`, `model`, `parent_run_id`, `delegation_level`, and (0.5.0) `tenant_id`. List views never load pause state, and `offset` is capped at 10,000.

**`RunDetail`** (from `get_run`): every `RunSummary` field plus `strategy`, `input_data`, `answer`, `error`, `failure_reason`, `cancel_requested` (`True` between a `cancel_run` request and the run reaching a terminal status), `pause_requested` (`True` between a `request_pause` request and the run pausing), and (0.5.0) `error_info`, the structured summary of a provider failure that ended the run (`None` otherwise).

**`StoredEvent`** (from `get_events`): `sequence_index`, `iteration_index`, `event_type`, `correlation_id`, `data`, `created_at`.

**`LLMCall`** (from `get_llm_calls`): `iteration`, `provider`, `model`, `input_tokens`, `output_tokens`, `total_tokens`, `cache_read_input_tokens`, `cache_creation_input_tokens`, `cost_usd`, `duration_ms`, `provider_request`, `provider_response`, `created_at`.

**`ToolInvocation`** (from `get_tool_invocations`): `iteration`, `tool_name`, `tool_call_id`, `provider_tool_call_id`, `target`, `params`, `result`, `success`, `error`, `duration_ms`, `created_at`.

**`TraceEntry`** (from `get_traces`): `role`, `content`, `order_index`, `meta`, `created_at`, `phase` (`"commentary"` for an assistant message that ended in tool calls, `"final_answer"` for the answer turn, `None` for other roles and rows written before phases were recorded).

**`RunSubtree`**, **`SubtreeNode`**, **`RunUsage`** (from `get_subtree`) and **`RunNote`** (from `get_notes`) are described under [`get_subtree`](#get_subtree) and [`get_notes`](#get_notes).

**`PausePair`** (from `get_pauses`): `pause_sequence_index`, `pause_at`, `resume_sequence_index`, `resume_at`, `reason`, `pending_tool_calls`, `submitted_results`, `user_input`, and (0.5.0) `pause_id`, which you can pass back as `expected_pause_id=` to a `submit_*` call. `pending_tool_calls` carries the pending calls' ids, names and parameters, so `get_pauses` is the public way to read a client tool's call ids when you are not holding the original `RunResult` (see [Client-side tools](/docs/recipes/client-tools)). `pause_id` is `None` for pauses recorded before 0.5.0.
