# RunStore

`RunStore` is the public, read-only way to query everything Dendrux persisted about a run. It is a plain Python object you can call from any code (routes, admin scripts, background jobs) it supports routes and inspection tools owned by your app.

[//]: # "docs-test: skip - fragment: relies on `run_id`, defined by setup shown elsewhere"

```python
from dendrux.store import RunStore

store = RunStore.from_database_url("sqlite+aiosqlite:///app.db")
async with store:
    run = await store.get_run(run_id)
    events = await store.get_events(run_id)
```

## Constructors and lifecycle

[//]: # "docs-test: skip - API signature listing, not runnable code"

```python
@classmethod
def from_database_url(database_url: str, *, blob_store: BlobStore | None = None,
                      database_options: dict[str, Any] | None = None) -> RunStore   # store owns the engine
@classmethod
def from_engine(engine: AsyncEngine, *, blob_store: BlobStore | None = None) -> RunStore   # caller owns the engine
async def close() -> None
```

Both constructors take `blob_store=` (a `BlobStore`) when the deployment keeps image bytes outside the database; use the same store as the `Agent`. `from_database_url` also takes `database_options=` (extra `create_async_engine` options; non-SQLite engines default to `pool_pre_ping=True` and `pool_recycle=1800`). Two members relate to images:

[//]: # "docs-test: skip - API signature listing, not runnable code"

```python
store.blobs                                                       # BlobAccessor: read, info, references, purge, collect_garbage
async def read_image(run_id: str, sha256: str, *, tenant_id=...) -> bytes
```

`read_image` returns verified image bytes only if the run exists (and matches `tenant_id` when given) and references that blob; otherwise `BlobNotFoundError`, the same error for a missing blob, another tenant's blob and an unreferenced one. It is the call to put behind your own authorization when you serve images from a route. `store.blobs.purge(...)` and `store.blobs.collect_garbage(...)` are the only writes `RunStore` has. See [Images](/docs/recipes/images#storage).

`from_database_url` creates and owns an engine; `close()` (or exiting the `async with`) disposes it. `from_engine` reuses an engine you already have; `close()` is then a no-op and you dispose the engine yourself. `RunStore` is an async context manager.

## Tenant scope

Every read takes a keyword-only `tenant_id`, where `TenantScope` is `str | None | UNSCOPED`. The older reads (`list_runs`, `count_runs`, `get_run`, `get_events`, `stream_events`, `get_llm_calls`, `get_tool_invocations`, `get_traces`, `get_pii_mapping`, `get_pauses`, `get_pause_page`, `get_subtree`, `get_notes`, `read_image`) default to `UNSCOPED`. `get_pending`, `follow` and `get_event_view` have **no default**: leaving `tenant_id` out is a `TypeError`.

| Value | Reads |
| --- | --- |
| `"acme"` | that tenant's runs only |
| `None` | untenanted runs only (changed in 0.5.0: `None` used to mean "all" on `list_runs` and `count_runs`) |
| `UNSCOPED` (the default) | every tenant |

A run outside the scope behaves exactly like a missing one, and what "missing" looks like depends on the method:

| Method | Missing or foreign run |
| --- | --- |
| `get_run` | returns `None` |
| `get_events`, `get_llm_calls`, `get_tool_invocations`, `get_traces`, `get_pauses` | return `[]` |
| `get_pause_page` | returns `([], False)` |
| `get_pii_mapping` | returns `{}` |
| `get_notes` | unscoped: returns `[]`; with a `tenant_id`: raises `RunNotFoundError` |
| `get_subtree`, `get_pending`, `follow` (on start), `get_event_view` | raise `RunNotFoundError` |
| `read_image` | raises `BlobNotFoundError`, the same error as for a missing blob |

An empty result is therefore never proof that a run exists. Check `get_run` (or `get_pending`) first when your route needs a 404. The scope is part of the same query as the read. Pass the authenticated caller's tenant from every route of your own; see [Multi-tenancy](/docs/architecture/multi-tenancy).

```python
from dendrux import UNSCOPED
```

### Arguments are validated

Every read, `get_pending` and `follow` checks its arguments before it queries, and refuses with a `ValueError` whose message is fixed and does not echo the rejected value (Dendrux logs `code=read_argument_invalid` with the argument name). One exception: the `offset` cap on `list_runs` and `count_runs` names the cap and the integer you passed, because the value is a number you chose. A route can map it to HTTP 400.

- Run ids and string tenant ids are non-empty strings of at most 255 characters with no NUL and no unpaired surrogate. `get_run(None)` therefore raises (it used to return `None`).
- Cursors fit a 32-bit integer; `limit` and `offset` are integers (not `bool`); `offset` is at most 10,000.
- `event_types` and `status` hold at most 100 entries.
- `metadata_filter` is a dict of at most 32 keys matching `[A-Za-z0-9_-]{1,128}`, with scalar values (strings up to 4096 characters, finite numbers, `bool` or `None`). Nested values are not supported.
- Date filters (`started_after`, `started_before`, `before`) are timezone-aware `datetime` values.
- Boolean flags (`include_payloads`, `until_terminal`, `active_pause`, `undelivered_only`) must be real `bool` values. A string such as `"false"` raises instead of being read as true.
- `read_image` with a value that is not a SHA-256 hex digest raises `BlobNotFoundError`, like a missing image.

async def get_pii_mapping(run_id: str) -> dict[str, str]

| Method | Returns | Notes |
| --- | --- | --- |
| `list_runs` | `RunSummary` page | Filters AND together. `metadata_filter` is exact-match across `meta` keys. |
| `count_runs` | `int` | Same filters as `list_runs`, for pagination totals. |
| `get_run` | `RunDetail` or `None` | One run's full anchor row. |
| `get_events` | `StoredEvent` list | `after_sequence_index` is a strict `>` cursor (reconnect-safe). See [Event ordering](/docs/architecture/event-ordering). |
| `stream_events` | async iterator | Raw events, never ends on its own. Without `tenant_id` it reads any tenant's run and prints a `DeprecationWarning`; prefer `follow`. |
| `get_pending` | `PendingPause` or `None` | What a paused run is waiting on. See [Pending and live reads](#pending-and-live-reads). |
| `follow` | `Follow` (async iterator) | A hardened live feed. See [Pending and live reads](#pending-and-live-reads). |
| `get_llm_calls` | `LLMCall` list | Per-LLM-call usage, cache, raw payloads. |
| `get_tool_invocations` | `ToolInvocation` list | Per tool execution: params, result, success. |
| `get_traces` | `TraceEntry` list | Conversation messages in order. |
| `get_pauses` | `PausePair` list | HITL pause/resume cycles, first `limit` pairs (1 to 1000). Past pauses' arguments and the person's `user_input` are hidden unless `include_payloads=True`. |
| `get_pause_page` | `(pairs, truncated)` | Same, plus an honest flag for more pairs than `limit`. |
| `get_pii_mapping` | `dict[str, str]` | Placeholder to real value. Real personal data: for trusted server code only. See [PII redaction](/docs/architecture/pii-redaction). |
| `get_subtree` | `RunSubtree` | A run, its delegated descendants and live rolled-up usage. |
| `get_notes` | `RunNote` list | Inbox notes submitted with `submit_note`, delivered or not. |

### Pending and live reads

Two calls exist to serve a frontend from your own routes. Both require an explicit `tenant_id` (a string, `None`, or `UNSCOPED`; leaving it out is a `TypeError`) and never fail open. The recipe is [Build your own read routes](/docs/recipes/build-your-own-read-routes).

[//]: # "docs-test: skip - API signature listing, not runnable code"

```python
async def get_pending(run_id: str, *, tenant_id: TenantScope) -> PendingPause | None

def follow(run_id: str, *, tenant_id: TenantScope, after_sequence_index: int | None = None,
           include_payloads: bool = False, until_terminal: bool = True,
           max_duration_s: float | None = 900.0) -> Follow
```

**`get_pending`** returns `None` when the run is not paused and raises `RunNotFoundError` for a missing or foreign run. A `PendingPause` has `run_id`, `status`, `kind` (`client_tool`, `approval`, `input` or `paused`), `pause_id`, `tool_calls` (a list of `PendingToolCall` with `id`, `name`, `target`, `params`, `approval` and `args_hidden`), `question`, `options`, `reason`, `message` and `budget_exceeded`; `to_dict()` gives the `run.paused` event shape plus those fields. It is bounded: the run's history is never loaded, and on Postgres a stored pause is converted to JSON once per read whatever its size. A client-tool or requested pause costs one projected read; an approval or input pause adds the active-pause sequence and the recorded model arguments, three bounded reads in all. `params` depend on the kind:

| Kind | `params` |
| --- | --- |
| `client_tool` | The arguments the client tool receives. With the default `PII(restore="all")` these hold real values. Authorize the actor before you show them. |
| `approval`, `input` | The arguments exactly as the model sent them (PII placeholders), which is what a person approves. If the recorded model arguments are unavailable, `params` is `None` and `args_hidden` is `True`: resolve that pause on the server, never approve an empty object. |

`get_pending` reports the run you ask about: for a run that delegated, list the tree with `get_subtree` and call `get_pending` for each waiting node.

**`follow`** yields `StoredEvent` items, `FollowHeartbeat` when quiet, and a final `FollowEnd(reason, cursor)` where `reason` is `terminal`, `max_duration`, `lagging` or `error`. Use `async for` (after `await follow.start()` if you want to check the scope and capacity before sending response headers) and `await follow.aclose()` when done. `follow.drained_terminal` is `True` when the run is already finished and has nothing left to send; a route can answer 204 without iterating. A shared poller serves every follower of a run in your process, so database load grows with watched runs, not with open connections, and one follower costs a small constant number of statements however many pauses the run has. Events pass through the [redacted view](#redacted-views) unless `include_payloads=True`.

Follower limits (`FollowCapacityError`, answer 503 with a short `Retry-After`):

- at most **500 followers per store** (`RunStore.follow` uses one `EventFeed` per store);
- at most **100 per tenant scope** by default, a fifth of the store cap. The cap is per scope, not per user: each string `tenant_id` is one scope, all untenanted (`tenant_id=None`) followers together are one scope, and all `UNSCOPED` followers together are one scope. `FollowCapacityError.per_tenant` tells the two caps apart;
- **900 seconds** per follow by default (`max_duration_s`), ending with a resume cursor.

A single-tenant app that serves more than 100 live readers per process builds its own feed, and calls `feed.follow(...)` instead of `store.follow(...)`:

[//]: # "docs-test: skip - fragment: relies on `store`, defined by setup shown elsewhere"

```python
from dendrux.store import EventFeed

feed = EventFeed(store, max_followers=2000, max_followers_per_tenant=None)
```

`max_followers_per_tenant=None` turns the per-scope cap off; a number sets it. The caps are per process: size them with your worker count and database pool.

**`get_event_view(run_id, event, *, tenant_id, include_payloads=False)`** verifies that the run is in scope. Pass only events read from that same run; `StoredEvent` has no run ID to verify the association. It resolves the active pause and uses the recorded model-sent approval arguments. Prefer it when paging raw `get_events` rows for a UI. Each call costs one status query plus, for a pause event, an active-pause read, so keep pages small and use `follow` for live delivery.

**`redact_event(event, *, include_payloads=False, active_pause=False)`** is a conservative standalone filter with no database context. It cannot prove which names are declared tools, so it shows `<unknown_tool>` for them, and unverified active approval or input arguments are hidden (`params=None`, `args_hidden=True`); never replace them with empty args. All feed and pending types, `EventFeed`, `redact_event` and `RunStore` are importable from `dendrux.store`.

The feed bounds iteration; your HTTP transport must bound blocked sends and call `aclose()` in `finally`, including if no generator iteration begins.

### Redacted views

`follow`, `get_event_view`, `redact_event`, `get_pauses` and `get_pause_page` take `include_payloads` (default `False`). With the default, a stored event is shown through a field allowlist: every event type has a rule, and a field survives only if it is one of these:

- a Dendrux enumeration or constant code (a run status, a stop reason, a pause reason, a budget metric, a tool result code);
- a Dendrux-generated id or digest (run, pause and note ids, content hashes);
- a number or a boolean;
- a developer-declared name that Dendrux can prove from configuration (the agent name, skill names, guardrail ids and the tool names the run recorded in its `tools.declared` event, plus Dendrux's own skill tools).

Everything else is hidden or replaced with a placeholder: text written by a model, a provider, a tool, an MCP server, a hook or a client. In practice that means the system prompt, provider requests and responses, tool arguments and results, PII mappings, free text such as a person's answer (`run.resumed.user_input`), a reviewer's denial reason, exception text (`run.error.error`; use `error_info`), image descriptions and a pause's `message`. `error_info` keeps only `category`, `retryable`, `error_type`, a built-in `provider` label, `status_code` and `timeout_reason`; `safe_message`, `model` and `provider_code` are hidden because they can carry vendor text. Tool call ids are hidden too, apart from the active pause's. Placeholders you may see:

| Placeholder | Meaning |
| --- | --- |
| `<unknown_tool>` | A tool name Dendrux cannot prove is a declared tool (a name the model invented, a run with no `tools.declared` record, or `redact_event` without database context). |
| `<mcp_tool>` | A name the run recorded as coming from an MCP server. |
| `<custom_kind>` | A guardrail finding kind that is not one of Dendrux's built-in detectors. |
| `<custom_provider>` | A provider label that is not one of Dendrux's built-in adapters. |
| `<unknown_code>` | A tool result code that is not one Dendrux writes. |
| `<unknown_skill>` | A skill name the model invented. |

**The active pause is the exception.** A client has to act on it, so the arguments, call ids and tool names of the pause the run is waiting on stay visible in `run.paused`, in `get_pending` and in the matching `approval.requested` event. Authorize the actor first: client-tool arguments can hold real personal data. Past pauses are redacted like everything else. `include_payloads=True` is for trusted operators.

**What this protects against.** Redacted readers protect against untrusted *data*: text supplied by models, provider responses, tool results, MCP servers, hook return values and clients. They do not protect against hostile code running in your process. A custom provider, strategy, state store or hook is Python with the full privileges of your server, so it could write any record or read around the redactor, and no library can defend against that. Review that code as you review the rest of your server.

> **Known limit.** A tool name is shown only when the run's `tools.declared` event lists it; that event is written by Dendrux at the start of each run segment from the tools declared in code, never from MCP discovery or model output. Records written by in-process code you control are inside the boundary above. Runs created before 0.5.0 have no such event and show `<unknown_tool>` for tool names outside the active pause.

### `get_subtree`

A delegated run has child runs, which may have children of their own. `get_subtree` returns the whole tree under a run, with usage rolled up:

[//]: # "docs-test: skip - fragment: relies on `run_id`, defined by setup shown elsewhere"

```python
tree = await store.get_subtree(run_id)
for node in tree.nodes:                       # breadth-first, root first
    print("  " * node.depth, node.run.run_id, node.run.status, node.usage.known_cost_usd)
print(tree.usage.input_tokens, tree.usage.output_tokens, tree.usage.cost_usd)
```

- `RunSubtree` has `root_run_id`, `nodes` (a `SubtreeNode` each: `run` as a `RunSummary`, `depth` below the root, and that run's own `usage`), `usage` (the sum over every node) and a `root` property.
- `RunUsage` has `input_tokens`, `output_tokens`, `cache_read_tokens`, `cache_write_tokens`, `reasoning_tokens`, `cost_usd`, `known_cost_usd`, `unpriced_calls` and `llm_calls`. `known_cost_usd` is the sum over the priced calls; `cost_usd` equals it only when every call was priced and is `None` when any was not (an unknown cost is never counted as zero).
- **`RunSubtree.usage` is the live rollup of successfully recorded `llm_interactions`.** It includes unfinished runs, but interaction writes are best-effort, so it is not a billing guarantee. The `total_*` fields on each node's `RunSummary` are the snapshots persisted on `agent_runs` and may lag, or read 0 for a run still in progress. Use `usage` for live spend; this is also the figure [budgets](/docs/architecture/budget) enforce.
- The reads are best-effort, not one snapshot transaction. A run that is still writing can make the node list and the usage differ by a call or a child.
- **Tenancy.** Omit `tenant_id` (or pass `UNSCOPED`) for a trusted, unscoped read of all descendants. Pass a string to scope to that tenant, or an explicit `None` to scope to untenanted runs. The root must be in scope (otherwise it reads as missing) and so must every descendant; a run outside the scope is excluded together with everything below it.
- Raises `RunNotFoundError` if the root does not exist or is out of scope.

### `get_notes`

[//]: # "docs-test: skip - fragment: relies on `run_id`, defined by setup shown elsewhere"

```python
notes = await store.get_notes(run_id, undelivered_only=True)
```

The run's [inbox](/docs/architecture/inbox) notes as `RunNote` records (`note_id`, `run_id`, `text`, `metadata`, `created_at`, `delivered_at`, `delivered_iteration`) in delivery order. `delivered_at` is `None` for a note the model has not seen. With `tenant_id=` the run must belong to exactly that tenant or `RunNotFoundError` is raised; without it, a missing run gives an empty list.

> Since 0.5.0 `dendrux.store.RunNotFoundError` and `dendrux.errors.RunNotFoundError` are the same class, constructed from a run id (`RunNotFoundError("01J...")`). One `except` clause covers `Agent` methods and `RunStore` reads. Code that raised it with a message must pass the run id instead.

### Time and type filters

`get_events`, `get_llm_calls` and `get_tool_invocations` accept `before=`, an exclusive upper bound on `created_at`. It must be timezone-aware; a naive datetime raises `ValueError`. `get_events` also accepts `event_types=`, a list of event type strings to keep (an empty list matches nothing):

[//]: # "docs-test: skip - fragment: relies on `run_id`, defined by setup shown elsewhere"

```python
from datetime import UTC, datetime

governance = await store.get_events(run_id, event_types=["policy.denied", "approval.requested"])
old = await store.get_llm_calls(run_id, before=datetime(2026, 10, 1, tzinfo=UTC))
```

### `metadata_filter`

`list_runs` and `count_runs` accept `metadata_filter: dict[str, Any]`. It does exact-match equality across every key in the run's `meta` JSON, AND across keys (`jsonb @>` on Postgres, repeated `json_extract` on SQLite). Keys are restricted to `^[A-Za-z0-9_-]+$`; nested paths are out of scope. The canonical use is per-conversation observability:

[//]: # "docs-test: skip - fragment: continues after a step that closed the store"

```python
runs = await store.list_runs(metadata_filter={"thread_id": "thread_abc"})
total = await store.count_runs(metadata_filter={"user_id": "u_123"}, status="error")
```

See [Chatbot threads](/docs/recipes/chatbot-threads) for the full pattern.

## Record types

All returned from `dendrux.store`. Fields, exact as persisted:

**`RunSummary`** (from `list_runs`): `run_id`, `agent_name`, `status`, `created_at`, `updated_at`, `iteration_count`, `total_input_tokens`, `total_output_tokens`, `total_cache_read_tokens`, `total_cache_creation_tokens`, `total_cost_usd`, `model`, `parent_run_id`, `delegation_level`, and (0.5.0) `tenant_id`. List views never load pause state, and `offset` is capped at 10,000.

**`RunDetail`** (from `get_run`): every `RunSummary` field plus `strategy`, `input_data`, `answer`, `error`, `failure_reason`, `cancel_requested` (`True` between a `cancel_run` request and the run reaching a terminal status), `pause_requested` (`True` between a `request_pause` request and the run pausing), and (0.5.0) `error_info`, the structured summary of a provider failure that ended the run (`None` otherwise).

**`StoredEvent`** (from `get_events`): `sequence_index`, `iteration_index`, `event_type`, `correlation_id`, `data`, `created_at`.

**`LLMCall`** (from `get_llm_calls`): `iteration`, `provider`, `model`, `input_tokens`, `output_tokens`, `total_tokens`, `cache_read_input_tokens`, `cache_creation_input_tokens`, `cost_usd`, `duration_ms`, `provider_request`, `provider_response`, `created_at`.

**`ToolInvocation`** (from `get_tool_invocations`): `iteration`, `tool_name`, `tool_call_id`, `provider_tool_call_id`, `target`, `params`, `result`, `success`, `error`, `duration_ms`, `created_at`.

**`TraceEntry`** (from `get_traces`): `role`, `content`, `order_index`, `meta`, `created_at`, `phase` (`"commentary"` for an assistant message that ended in tool calls, `"final_answer"` for the answer turn, `None` for other roles and rows written before phases were recorded).

**`RunSubtree`**, **`SubtreeNode`**, **`RunUsage`** (from `get_subtree`) and **`RunNote`** (from `get_notes`) are described under [`get_subtree`](#get_subtree) and [`get_notes`](#get_notes).

**`PausePair`** (from `get_pauses` and `get_pause_page`): `pause_sequence_index`, `pause_at`, `resume_sequence_index`, `resume_at`, `reason`, `pending_tool_calls`, `submitted_results`, `user_input`, and (0.5.0) `pause_id`. `pending_tool_calls` carries the pending calls' ids, names and parameters, so `get_pauses` is the public way to read a client tool's call ids when you are not holding the original `RunResult` (see [Client-side tools](/docs/recipes/client-tools)). `pause_id` is `None` for pauses recorded before 0.5.0. By default past pauses' arguments, call ids and `user_input` are hidden; pass `include_payloads=True` for a trusted view.
