# Log codes and what to do

> Generated by `packages/python/tools/gen_log_codes.py`.
> Edit the registry, then regenerate.

Every checked log line carries `code` and `kind`, plus `run_id` and `tenant_id` when set.
Other fields are declared per code. Identifiers are validated; text uses closed enums.
Invalid fields raise in tests. Production drops them and emits one `log_field_dropped`
diagnostic containing only a count. Vendor messages and payloads are never log fields.

Provider codes use closed per-provider tables.
Present unknown codes become `provider_unknown`.
Missing or invalid codes remain unset. Category and HTTP status remain independent.

| `tenant_scope_required` | WARNING | `code`, `entry`, `kind`, `run_id`, `tenant_id` | A strict tenancy entry has no explicit tenant scope. | Pass the intended tenant scope. |

## What to alert on

- `reclaim_limit` at any rate: inspect the run and worker crashes.
- `run_fenced` above a small sustained rate: inspect worker turnover and lease sizing.
- `notifier_degraded` lasting more than one minute: inspect the listener connection.
- `sweep_cap_reached` on every sweep: run more often or raise the scan bound.
- `follow_capacity` or `follow_tenant_capacity`: reduce followers or raise their cap.
- `log_field_dropped`: fix the emitting call without adding raw values to diagnostics.
